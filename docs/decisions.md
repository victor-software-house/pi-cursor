# pi-cursor decisions

> **Status:** Public release candidate as of 2026-09-03. The implementation, deterministic package
> gates, bounded live checks, `/cursor` TUI proof, and complete reachable-history privacy audit are
> complete. The operator authorized the first functional `0.0.1` release; Changesets and GitHub
> Actions now own versioning, npm OIDC publication, tagging, and the GitHub Release.

> Earlier decisions below are chronological. Later entries explicitly supersede earlier scope or
> evidence decisions.

- 2026-09-02 Public package `pi-cursor-inference` on npm (unscoped, MIT; GitHub repository stays `pi-cursor`) is a clean proof of concept of Cursor as a plain inference provider over `aiserver.v1.InferenceService/RunInference`. It is not a port of the private `@victor-software-house/pi-cursor` extension's operator features.
- 2026-09-02 Scope is a working provider plus login. The usage dashboard is out; it is larger than the provider and not yet fully tested.
- 2026-09-02 Machine identity is derived from the host with Cursor's own algorithm, never read from an installed IDE. Evidence: Cursor 3.18.9 `main.js` (`id.js`, `macAddress.js`, `telemetryUtils.js`): `telemetry.machineId` = SHA-256 of the OS hardware id string (`ioreg` IOPlatformUUID on darwin, `MachineGuid` on win32, `/etc/machine-id` or hostname on linux, `smbios.system.uuid` on freebsd; random UUID fallback); `telemetry.macMachineId` = SHA-256 of the first `os.networkInterfaces()` MAC not in `{00:00:00:00:00:00, ff:ff:ff:ff:ff:ff, ac:de:48:00:11:22}`. Both recomputed locally on 2026-09-02 and equal to the IDE's stored values byte for byte. The checksum omits the `/mac` suffix when no MAC exists, as Cursor does.
- 2026-09-02 `x-cursor-client-os` and `x-cursor-client-arch` follow `process.platform` / `process.arch`, matching Cursor's `getClientOS()`. The private extension's `darwin`/`arm64` hardcode is not carried.
- 2026-09-02 Credentials use Pi's native OAuth provider contract (`auth.oauth` with `login`, `refreshToken`, `getApiKey`) so `/login cursor` works and Pi owns storage and refresh. No SQLite, no 1Password, no keychain reads. A `PI_CURSOR_TOKEN` environment variable remains the headless path.
- 2026-09-02 Single account. Multi-account is deferred until a public user asks for it.
- 2026-09-02 The reconstructed `inference.proto`, the artifact lock (version, commit, URL, DMG hash, module ids), and a synthetic tool round-trip corpus are committed as public evidence of the wire contract. The DMG, extraction scripts, and network drift gates from the private repository are not carried.
- 2026-09-02 Repository starts private and becomes public at the first npm release.
- 2026-09-02 npm rejected `pi-cursor` (“too similar to existing package cli-cursor”) and `pi-cursor-provider` was taken. `pi-cursor-inference@0.0.0` was published manually by the operator as the name reservation and Changesets bootstrap; the first functional release is `0.0.1` through the Version Packages PR. The npm registry records the owning account on the public placeholder.
- 2026-09-02 CI and release use GitHub-hosted `ubuntu-24.04` runners. Namespace and other paid runner providers are intentionally excluded because this public project has GitHub-hosted runner capacity.
- 2026-09-02 Keep the public extraction extremely selective. Port only the runtime required for provider registration, OAuth login/refresh, host-derived identity, catalog preflight, RunInference request/transport/stream mapping, and their narrow tests. Do not carry account/database abstractions, operator commands, usage UI, keychain/1Password support, capture/extraction machinery, broad CLI proto trees, or historical artifacts.
- 2026-09-02 `@victor-software-house/pi-type-kit` is the sole permitted private build dependency. Import exact named helpers and bundle them into the minified artifact; Pi peers remain external. Explicit tree shaking plus packed-bundle checks must prove unused type-kit modules, package names, and source paths are absent. No other private package dependency is permitted.
- 2026-09-02 The published artifact is one minified ESM bundle with no source map plus the minimal declaration for the extension entry.
- 2026-09-02 Cursor login polling is the captured CLI `GET /auth/poll?uuid=<uuid>&verifier=<verifier>` flow, not POST. The refresh endpoint remains prior art only and blocks the functional release until measured.
- 2026-09-02 Catalog schema is separately pinned to `cursor-agent 2026.09.02-fa0c06e` and reduced to ten messages for exactly `AvailableModels`, `GetUsableModels`, and `GetDefaultModelForCli`. These captured Connect unary calls use `node:https`; they do not share the managed-inference HTTP/2 run.
- 2026-09-02 Dynamic catalog refresh is fail-closed. A failed network refresh clears persisted and in-memory Cursor models before surfacing the error; it never retains a stale selectable model list.
- 2026-09-02 Operator stopped the project before a functional release. Keep the repository private, preserve the implementation as unreleased research, leave `pi-cursor-inference@0.0.0` as the blank npm reservation, and disable release automation.
- 2026-09-02 Operator resumed development the same day. The login challenge derivation was corrected to `base64url(sha256(verifier-string))`: the captured 2026-08-25 poll exchange reproduces the server challenge exactly from the verifier string, and the extracted CLI, IDE agent-host, and SDK auth clients all agree. Hashing the raw 32 verifier bytes (the previously committed form) produces a challenge the server never accepts, so polling stays 404 until timeout. Release automation remains disabled pending an explicit operator decision.
- 2026-09-02 Measured live login and refresh. The corrected challenge derivation completed a real browser login and poll. `POST /auth/exchange_user_api_key` rejects both login JWTs as bearer with 401 `Invalid User API Key` (access and refresh both measured); that endpoint consumes only a Cursor User API Key, which the CLI stores as a separate `cursor-api-key` credential that browser logins never write. The CLI, IDE agent-host, and SDK never refresh a browser login at all: their refresh callbacks bearer `getApiKey() ?? CURSOR_API_KEY` and keep the current token when absent.
- 2026-09-02 Exhaustive extracted-source audit found the real refresh mechanism in the pinned 3.18.9 IDE workbench, and it was measured live: `POST https://api2.cursor.sh/oauth/token` with `{grant_type: "refresh_token", client_id: "KbZUR41cY7W6zRSdpSUJ7I7mLYBKOCmB", refresh_token: <PKCE login refresh JWT>}` returns 200 with a fresh 60-day `access_token` (plus `id_token` and `shouldLogout: false`). The refresh JWT is durable and non-rotating: repeated grants with the same token each returned 200, and the response carries no `refresh_token`. The `x-cursor-client-type` header the workbench sends is optional (measured 200 without it). The workbench skips the grant while the access JWT has more than ~53 days left (`Qrr = 1272*60*60*1e3 ms`) and stores the new access token as both access and refresh; pi-cursor instead keeps the original refresh token, which stays valid. `shouldLogout: true` means server-side revocation (e.g. MDM sign-in policy) and is surfaced as a re-login error. oh-my-pi's `exchange_user_api_key` refresh prior art is wrong (measured 401 for both JWTs).
- 2026-09-02 The first live `/login cursor` proof succeeded end to end, but completing the login in the browser launched the installed Cursor IDE: the portal defaults a missing `redirectTarget` to `ide` (its JS accepts `{cli, origin, sand}`, else `ide`) and fires the Cursor deep link on completion, which macOS routes to the installed app. The poll was unaffected. pi-cursor now sends the portal's own `redirectTarget=cli` — the CLI's actual parameter — which suppresses the deep-link launch and changes nothing in the auth contract (same challenge, poll, and refresh endpoints).
- 2026-09-02 Operator reversed the usage-surface exclusion: the `/cursor usage` pane moves from the plan's non-goals into scope. Provenance stays the private stack's measured implementation — the 2026-08-18 usage capture for the wire shape, the CLI renderer for every unit (hard limit dollars, int32-max unlimited sentinel, cents fields, 0–100 percents), and the DashboardService closure from the pinned CLI schema. Private build dependencies are bundled like `pi-type-kit`.
- 2026-09-02 Operator set the parity rule: auth and refresh must come from the same client whose inference pi-cursor mirrors — no mixing clients, no invented shapes. The pinned inference transport is the IDE 3.18.9 agent-host (`657.js`), and its credential provenance is now traced end to end: the agent-host extension's `credentialManager` (`Is` class in `extensions/cursor-agent-host/dist/main.js`) reads `cursor.getCursorAuthToken()` — the workbench-managed token — its `getApiKey()` is always undefined, and its `setAuthentication` merely executes the `cursorAuth.triggerTokenRefresh` command. The IDE's credential lifecycle is therefore entirely workbench-owned: workbench PKCE login → `storageService` (`cursorAuth/accessToken`/`cursorAuth/refreshToken`, not the CLI keychain) → agent-host consumes the token for inference → workbench renews it. pi-cursor's auth was realigned to the workbench in the same change: login URL sends `supportsSelectedTeamLogin=true` (the later portal-redirect decision above adds the CLI target solely to suppress the IDE deep link); the poll is a fixed 500 ms GET interval for the ~180 s window with no backoff and no error cap (the workbench interval swallows transient failures), sending the workbench header set (`traceparent`, `x-ghost-mode: implicit-false`, `x-new-onboarding-completed: false`, `x-cursor-client-type: ide` — the workbench's own default-state values); the refresh grant adds `x-cursor-client-type: ide` and the workbench's 20 s deadline; a `403` poll carrying the MDM sign-in-policy sentinel surfaces as a policy error while every other failure keeps polling. The workbench's store-access-as-refresh quirk stays uncopied (measured deviation, recorded above). The CLI-shaped 150-attempt backoff poll and the `PI_CURSOR_API_KEY` refresh branch were removed.
- 2026-09-02 Operator required Max Mode to default off and remain configurable. Formatted pinned IDE 3.18.9 workbench source proves ordinary `composer`, `cmd-k`, `composer-ensemble`, `plan-execution`, `spec`, `deep-search`, and `quick-agent` model configs default `maxMode: false`; only the distinct `background-composer` config defaults true. The model picker stores a separate boolean, the variant solver may select a max-only variant and different parameter values, `buildRequestedModel` sends it as `InferenceRequestedModel.max_mode`, and `runReady` returns the concrete resolved model/max-mode state. pi-cursor now defaults false and accepts explicit `samplingParams.cursorMaxMode: true` per model/request.
- 2026-09-02 Operator required the RunInference mapper to stop silently discarding known response arms. Formatted IDE source proves the stream adapter exposes `usage`, `extendedUsage`, `providerMetadata`, `invocationId`, and final `responseInfo` as first-class side channels; applies `imageDescriptions` to message-side provider data; and treats substantive `responseInfo.messages` as the authoritative final response. pi-cursor now mirrors that fallback, preserving signature-only reasoning, final text/tool calls, response id/model/timestamp, exact provider metadata, image descriptions, and inference-extra data in the final message/diagnostics. Every received arm is counted in a `cursor-inference-response` diagnostic. The request builder also forwards the IDE's explicit `max_tokens`, `temperature`, `top_p`, and `stop_sequences` model config fields.
- 2026-09-02 Grok 4.6 trace investigation: formatted agent-host source maps `InferenceThinkingStreamPart.text` to reasoning text and `signature` to a separate reasoning-signature event; the final response maps `reasoning_parts` the same way. Three bounded live RunInference measurements (trivial prompt, reasoning prompt, max mode false/true) produced an empty `text` and opaque signature only; the final `responseInfo.messages` also contained empty reasoning text with the same signature, so no displayable trace text exists on this lower-level stream. The IDE UI consumes the higher-level AgentService interaction stream; the pinned capture of `AgentService/RunSSE` contains `interaction_update.thinking_delta { text, thinking_style }` (506 text-bearing updates in the captured turn). That higher layer explains the visible IDE traces; pi-cursor deliberately remains on RunInference so Pi owns tools and transcript, and now preserves the opaque signature for continuation rather than dropping it.
- 2026-09-03 Catalog metadata is joined from the expanded selectable `GetUsableModels` families to complete `AvailableModels` rows by names, aliases, legacy slugs, and variant legacy slugs. Context windows, image support, and thinking support come from the matching base row. A separate `-max` model is published only when context, tooltip, or variants establish a meaningful difference. Captured Grok 4.6 therefore reports 256k with no redundant Max row; GPT-5.6 Sol reports 272k normally and 1M in its Max row. The selected generated catalog closure grows from ten to fourteen messages solely for the required nested parameter, tooltip, and variant metadata.
- 2026-09-03 Catalog-selected context is request state, not decorative metadata. Models carry `cursorContext` when the default catalog variant specifies it; the stream validates the value and threads it into both `InferenceRequestedModel.parameters` and the routing key. Max rows carry `cursorMaxMode: true`. Ordinary rows omit the redundant false default.
- 2026-09-03 `/cursor` and `/cursor usage` are the single-account operator surface. TUI mode renders Summary and Models tabs with configured Tab/cancel handling, `r` refresh, and `q` close. Outside TUI mode, print writes plain text, JSON emits a custom message event, and RPC uses a notification. Optional DashboardService failures are named misses and do not discard available usage; required-call failures fail visibly.
- 2026-09-03 The release artifact gate extracts the actual tarball, enforces its whitelist and bundle constraints, imports it under Node and Bun with five-second process guards, and loads it through Pi's real extension loader. The packed artifact must register `/cursor` and exactly one native `cursor` provider. Packed `/cursor help` must also produce plain text in print mode and a `cursor-command-output` message event in JSON mode. It does not use a fake `ExtensionAPI`.
- 2026-09-03 A fresh OAuth live proof passed all three catalog calls, DashboardService usage, and a bounded Composer 2.5 RunInference response. A visible isolated Pi TUI in Herdr rendered live Enterprise Summary and Models views, switched tabs, closed normally, and exposed one timed-out aggregate sample as a named partial miss. The temporary access token and pane were removed after proof. This establishes the current Darwin account path, not Linux/Windows host behavior or future server compatibility.
- 2026-09-03 Release readiness does not authorize publication. Keep `private: true`, version `0.0.0`, the GitHub repository private, release automation absent, and the npm placeholder untouched until the operator explicitly chooses to enable the first functional release.
- 2026-09-03 The routed `default` model may emit thinking even though its catalog row sets `supports_thinking: false`; that field governs selectable thinking controls, not whether a routed backend can stream reasoning. A bounded live capture produced 223 non-empty thinking characters, then final `responseInfo` carried the authoritative answer plus one redacted reasoning part with zero text. Replacing the whole streamed content with that final message briefly displayed thinking and then erased it. Final non-empty reasoning remains authoritative, but signature-only or redacted final reasoning now enriches the corresponding non-empty streamed thinking block with continuation metadata instead of deleting its text. Final text and tool calls remain authoritative.
- 2026-09-03 Final reconciliation is an always-on provider invariant, not a warning layer. When `responseInfo` exists, every completed streamed tool must match the final tool set by ID, name, and deep-equal arguments or the turn fails before local execution; `toolUse` derives only from reconciled tool content. Final text wins when present and streamed text is preserved when absent. Text equality, block counts, and character counts are retained in payload-free diagnostics; no prefix matching is used. Reasoning metadata matches by exact signature, then exact full text. A metadata-only final block may attach to streamed text by cardinality only when exactly one unmatched block exists on each side. Multi-block unmatched metadata remains as separate continuation blocks and is never paired by array index. Every bounded live inference test asserts the reconciliation diagnostic, and a paid arbitrary-tool turn proves exact streamed/final tool equality before continuation.
- 2026-09-03 Operator made strict reconciliation configurable and persisted assistant-message diagnostics opt-in. This supersedes only the preceding entry's “always-on” and “every response persists diagnostics” clauses. Strict reconciliation defaults on and still fails streamed/final tool ID, name, or deep-argument disagreement before execution. Turning it off accepts authoritative final content without cross-copy equality checks; local stream completion/JSON rules, duplicate-ID rejection, advertised-tool validation, and final parsing remain mandatory. Final-content assembly is always active, so absent final text falls back to streamed text and empty, signature-only, or redacted final reasoning can never erase non-empty streamed thinking. Diagnostics default off and add no Cursor diagnostic field to assistant messages; when enabled, the existing response diagnostic persists in session JSONL. Its reconciliation census is payload-free, while the same opt-in diagnostic may retain provider metadata, image descriptions, and inference-extra side channels. Bare `/cursor` opens a bundled `@victor-software-house/pi-components@0.2.17` selector with Usage and Settings; direct `/cursor usage` and `/cursor settings` remain available. The private component is an explicit second bundled build-dependency exception; Pi peers remain the only external runtime imports. GitHub Packages grants this repository Actions Read access to `pi-components`; the first CI attempt proved the grant was required by failing install with HTTP 403 before the package settings were updated and re-read.
- 2026-09-03 Operator selected the Quarter Turn identity after two design rounds. The final banner uses the exact subtitle `/cursor in Pi · unofficial routed Cursor inference`, a Graphite + Magenta palette, and four congruent slabs rotated 90 degrees around a cross-shaped void: three graphite legs are Pi-owned context/request/transcript work and the one magenta leg is Cursor inference. Production assets are paired light/dark banners and marks under `docs/`; text is converted to Geist Mono outlines, and README selects the field with `prefers-color-scheme`. The original A–D and revised E–H drafts remain ignored working material, not package assets.
- 2026-09-03 Before changing repository visibility, the exact GitHub-advertised `main` and `v0.0.0` history was audited without rewriting it. Full-history Gitleaks found no leaks across 33 commits. A second direct scan covered all 427 reachable objects and 238 distinct text blobs (1,847,673 decoded bytes), finding no private key, JWT, token, personal path/email, host identifier, live account usage value, non-loopback private network URL, or secret reference. Every broad candidate was classified as public business/npm identity, standard Cursor sentinel/public artifact evidence, synthetic fixture data, or loopback test state. The durable evidence is [`public-history-audit-2026-09-03.md`](public-history-audit-2026-09-03.md). The operator authorized making the GitHub repository public after this clean gate; that visibility change does not authorize npm publication.
- 2026-09-03 Operator explicitly authorized the complete first functional `pi-cursor-inference@0.0.1` release. Remove the manifest's private gate, restore the traceable Liquid-backed Changesets changelog, create one patch changeset, and publish only through the main-branch `release.yml` flow: Version Packages App PR, npm OIDC, Bun publish, exact tag, GitHub Release, and clean installed-artifact proof. Official Pi package docs govern discovery: retain the `pi-package` keyword and `pi.extensions` entry, use `*` for Pi core peer ranges, and provide `pi.image` as a stable 1200×240 PNG because the pi.dev gallery supports PNG/JPEG/GIF/WebP rather than SVG. The current `0.0.0` has the keyword but no published `pi` manifest and is absent from the gallery query; `0.0.1` must be re-queried after ingestion.
